# 记忆系统使用规范（通用范本 · 工作区/项目均适用）

本文件是根目录下 `docs/memory/` 记忆结构的使用说明（放在工作区根即为工作区级记忆库，放在项目根即为项目级记忆库）。AI 助手在对话中识别到归档意图时，必须严格按本规范执行。本文件为通用范本：所有路径均相对根目录书写，整库复制到其它机器、其它工作区或项目后可直接使用；使用处的根 AGENTS.md 与本文件同步维护。

## 一、定位与边界（重要）

- 本库登记工作区级记忆：跨项目的环境维护、版本管控、工具链配置等不专属单一项目的事项
- 各项目的业务记忆归各项目自己（在哪个项目作业，就在哪个项目的 `docs/memory/` 归档），例如项目 foo 的业务记忆在 `foo/docs/memory/`（相对根目录）；项目业务记忆不得写入本库，本库也不复制项目记忆
- 某次会话同时涉及工作区维护与某项目开发时：工作区部分归本库，项目部分归该项目

## 二、目录结构

```text
docs/memory/
├── _README.md                 # 本文件：使用规范（流程、检索链路、约束）
├── _INDEX.md                  # 索引导航页：分片清单 + 检索规则 + 维护规则（不存关键词）
├── _INDEX-<域>.md             # 词汇分片：按主题域拆分（版本管控/环境配置/AI工具链/其他）
├── YYYY.md                    # 年度关键词汇总（每年一份，如 2026.md）
└── YYYY/
    └── MM/
        └── DD/
            ├── core.md        # 当日核心索引：关键词 → 记忆文件 映射
            └── <模块名>.md    # 记忆文件：以当日调整的模块名称命名
```

## 三、三类记忆文件职责

### 记忆文件（<模块名>.md）

- 存放当日对话中涉及的具体工作内容：做了什么、改了哪些文件、关键决策、数据指标、踩坑结论
- 命名规则：以当日主要调整的模块名称命名（中文，≤15字）；同一天多个独立模块各建一个文件
- 内容必须事实化：包含具体文件名、路径、数字、结论，禁止空泛描述
- 文件头标注：归档日期、类型（环境维护／需求开发（need）／缺陷处理（feedback）／记忆系统维护）、来源、梳理汇入时间
- 内容结构（每次归档必须包含）：
  - 用户提示词：原话引用（blockquote），一字不改；口误/重复在梳理中注明，不修改原话
  - 实际需求梳理：将口语化提示词梳理成明确、无歧义的需求描述（含澄清后的歧义点）
  - 需求/问题描述、解决方案、涉及文件、代码变更摘要
- 同一模块文件多次归档按日期分段追加，历史段不覆盖

### core.md（当日核心索引）

- 提取当天所有记忆文件的核心关键词，建立 关键词 → 记忆文件 的映射（表格：关键词｜记忆文件｜摘要）
- core.md 只放索引和摘要，不放详细内容

### YYYY.md（年度汇总）

- 每年一个文件；汇总该年度所有月份的关键词，按月份分组（关键词：… + 记忆文件：YYYY/MM/DD/core.md）

## 四、归档触发与流程

- 触发词：用户说 "总结归档"（或同义：归档、总结并归档、记录一下、存档）。
- 回顾本轮对话，提取核心关键词（3-8 个，名词性功能/模块名为主，组合词优先，固定写法）
- 判断日期（用系统当前日期，禁止猜测）
- 创建/更新记忆文件（YYYY/MM/DD/<模块名>.md；已存在则追加）
- 创建/更新 core.md（关键词映射表新增行或更新摘要，不删除已有映射）
- 创建/更新 YYYY.md（对应月份段落追加关键词与当日 core.md 路径，去重）
- 更新词汇分片 _INDEX-<域>.md：判断主归属域，新增/合并关键词行，只增不删；一词只进一片

### 索引分片与紧凑格式

- _INDEX.md 只做导航（分片清单 + 检索规则），防单文件膨胀
- 分片内每行一个关键词，聚合全部日期：`关键词|(年/月1|月2/月1的日,月1的日|月2的日)`
- 示例：`记忆系统|(2025/10|12/21|01,22)` = 2025-10-21、2025-12-01、2025-12-22
- 跨年追加新括号组：`关键词|(2025/10/21)(2026/01/05)`
- 该关键词已存在则把新日期并入（升序），否则新增一行到对应分片；无法归类的进 _INDEX-其他.md（惰性创建）
- 拿不准分片时跨片检索：`grep 关键词 docs/memory/_INDEX-*.md`
- 单个分片超过 80 行时拆出子域分片，并更新 _INDEX.md 清单

## 五、检索方式（n 年后提问时）

1. _INDEX.md 确定分片（拿不准 grep 关键词 `docs/memory/_INDEX-*.md`）
2. _INDEX-<域>.md 按关键词命中日期
3. 进入 YYYY/MM/DD/core.md 看当日映射
4. 打开 <模块名>.md 看详细内容

AI 助手回答历史问题时必须主动走这条检索链路，不能只凭当前对话上下文回答。

## 六、约束

- 禁止编造：内容必须来自真实对话，不推测、不虚构
- 追加不覆盖；日期准确（系统时间）；中文命名；不存敏感信息（密码、密钥、证件号）
