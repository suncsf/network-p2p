## 实际需求梳理

1. 将「页面/弹窗标识标签规则（通用规范）」在本项目（Lattice）渲染端执行落地：
   - 页面/弹窗获得跨会话稳定的唯一标识（页面 #aXXX，弹窗 aXXXbYYY），徽章显示、点击复制；
   - 弹窗 ID 按 dialogKey（页面::语义名）解析：精确表 → 宿主前缀派生（按 key 固化）→ 随机兜底（按 key 固化），跨会话永久复用同一 ID；
   - 弹窗开→注册、所有关闭路径→注销，防注册表泄漏；
   - 持久化到 page-id-store.json；提供 AI 上下文快照 API。
2. 本项目结构与规范来源项目不同，需适配而非照搬：无 vue-router（App.vue 以 v-show/v-if 切换三视图）、无 AI/chat 模块（快照 API 预留）、无登录页（规范登录页特例不适用）。
3. 落地时机：项目骨架构建完成后（「继续，项目构建完成了」）。

## 需求/问题描述

- 项目此前无任何页面标识体系；照搬规范来源项目的 AppLayout/cachedPage 结构不可行（无 vue-router）。
- 落地中发现脚手架遗留缺陷：`@renderer` 别名在 electron.vite.config.ts 与 tsconfig.web.json 均错指 `src/renderer`（实际源码在 `src/renderer/src`），首次使用该别名即报 TS2307 Cannot find module（此前无人使用过 @renderer，故未暴露）。
- 通用规范的 eslint 验证项不可用：项目未配置 eslint。

## 解决方案

- 注册中心 `src/renderer/src/composables/usePageRegistry.ts`：FIXED_PAGE_IDS / FIXED_DIALOG_IDS / PAGE_DIALOG_BASE 三表；usePageId（页面，onUnmounted 自动注销）、registerDialog/unregisterDialog（弹窗）、getPageRegistrySnapshot()（AI 快照，预留）、initPageIdStore()（启动加载固化映射）。
- 页面承载适配：App.vue 作为布局层统一包 PageWrapper（等价 cachedPage）：workspace 用 v-show 常驻（≈keep-alive），server/settings 用 v-if 随切换装卸。
- 弹窗接线模式：`watch(visible)` 收拢注册/注销——覆盖取消/确定/右上角 X/ESC 全部关闭路径，无需逐个 close 函数补注销；徽章放 el-dialog `#header` 插槽（标题从 title 属性移入 header，flex + gap: 8px）。
- ID 分配：页面 a001 工作区 / a002 服务端 / a003 设置；弹窗 workspace::new-connection→a001b001、server::account-create→a002b001、server::grant-add→a002b002、server::node-permission→a002b003；随机兜底页段取 a800~afff 高位区间，避开固定表顺延范围。
- 持久化路径适配：规范来源项目为 `forall/config/page-id-store.json`，本项目 userData 为 `lattice` → `userData/config/page-id-store.json`；主进程 handler 提供 IPC `page-id:load` / `page-id:save`，preload 暴露 `window.api.pageId`。
- 徽章位置适配：left 248px → **228px**（本项目侧边栏 200px + 28 偏移），bottom: 16px。
- 别名缺陷修复：electron.vite.config.ts 与 tsconfig.web.json 中 `@renderer` 改指 `src/renderer/src`。
- SessionView/FilesView/TransfersView/ConnectView（内嵌或未挂载）不注册页面级标识；ElMessageBox.prompt 全局消息框不算业务弹窗。
