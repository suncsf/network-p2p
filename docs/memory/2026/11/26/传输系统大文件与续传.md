## 实际需求梳理

1. **大文件无上限**：移除 8MB 拦截；上传/下载/P2P 传输的数据不得再经 WS 命令通道整文件进内存。
2. **传输正确性**：本机同时当服务端+客户端（127.0.0.1/局域网 IP）时，P2P 推送必须弹确认并落盘；未开自动接收时不得自动接收。
3. **配置单入口**：服务端页与设置页重复的参数配置合并，设置页为唯一入口。
4. **统一传输面板**：覆盖上传与 P2P 收发，查询「进行中/已取消/已完成/已中断」，中断支持断点续传，支持取消与续传操作。

## 方案与实现

### 大文件链路（数据不经 WS 命令通道）

- `p2pPush` WS 命令：服务端从磁盘 64KB 分块直推对端接收端口；`FileOps.collectForTransfer` 目录递归展开（symlink 不跟随），要求 TRANSFER+DOWNLOAD 权限。
- 下载：≤8MB 走 data-URL 快速通道，>8MB 自动转 P2P 直连（保存对话框）；上传改 `uploadInit/uploadChunk/uploadFinish` 4MB 分块。
- 接收端授权：IPC `p2p:prepareReceive`（保存/选目录对话框 + 自动启动本机服务端 + `createLocalTransferGrant` 一次性 token）。

### 关键缺陷与修复（feedback）

1. **登录 token 覆盖 P2P 授权 token（根因级）**：`LatticeClient.request()` 会执行 `params: {...params, token: this.token}`，把 `p2pPush` 参数里的授权 `token` 覆盖成登录 token → 接收端 HELLO 校验失败直接断开（不弹确认、不落盘、拒绝原因被吞）。修复：授权字段改名 `p2pToken`（service.ts / FilesView.vue / 测试同步），发送端透传接收端 ERROR 帧原因。教训：**经 LatticeClient 的自定义授权字段不能用 `token` 名**。
2. **发送时序**：发送端曾不等 DECISION 就推块、接收端无 accepted 闸门 → 加 DECISION 等待 + accepted 闸门。
3. **自动接收失效**：配置里 `autoAccept:false` 却自动收。根因：`LatticeServer.updateConfig()` 只改自身，运行中的 `TransferManager` 用构造时快照；且 ServerView/SettingsView 双入口曾保存过 true。修复：新增 `TransferManager.update(patch)` 热更新（autoAccept/confirmTimeoutMs 即时生效，端口仍需重启），回归测试 `transfer-manager.test.ts`。
4. **大文件测试竞态**：首块落盘即 stat → 4784128/12582912 假失败；改为轮询至写满再断言。

### 配置合并

- ServerView 服务控制页只留启动/停止/运行状态/局域网 IP + 「前往设置」跳转（App.vue 接 `@go-settings`，注意该文件被并行改为 PageWrapper 结构）。
- SettingsView 为唯一参数入口（WS/P2P 端口、确认超时、接收策略、失败锁定），移入「自动选空闲端口」。

### 统一传输面板 + 断点续传

- **存储**：local.db migration version 2 建 `transfers` 表（id/kind/peer/name/remote_path/local_path/total/transferred/state/error/created_at/updated_at/session_id/resume + 2 索引）；新建 `src/main/transfers.ts` TransferStore（CRUD/interruptAll/clearFinished/getBySession/onChange）；启动时遗留 active → interrupted。已在用户真实 `~/.config/lattice/local.db` 副本上验证 1→2 迁移无损。
- **记录模型**（shared/protocol.ts）：`TransferState = active|completed|cancelled|interrupted`，`TransferKind = upload|p2p-send|p2p-recv`；同机收发两条记录按 sessionId 关联。
- **执行器**：新建 `src/main/transfer-runner.ts` TransferRunner——上传主进程循环（4MB 分块、250ms 节流进度）；取消（upload→uploadAbort 清理半成品不可续传；p2p-send→cancelPush；p2p-recv→abortReceive + `p2pPushStop` 通知发送端）；续传（upload 按 offset+uploadId，服务端不识别则自动重传；p2p-recv 复用原 sessionId 重建授权免对话框；p2p-send 重放推送）。
- **P2P 续传协议**（transfer.ts）：HELLO 带 `resume` → 接收端统计磁盘已有字节 → DECISION 返回 `offsets` → 发送端从断点续发；接收端 `'r+'` 续写（否则 `'w'` 截断）；完成前断开回调 `onInterrupted` 保留现场；授权 token 滑动续期（每次 HELLO +5min）；续传免二次确认。
- **service.ts 重构**：handleP2pPush 拆 `preparePush`（校验/收集/建记录）+ `executePush`（任务注册表 pushJobs + shouldAbort 轮询中止）；新增 WS 方法 `p2pPushStop`、`uploadAbort`；状态流转：未发出字节失败→cancelled，中途失败→interrupted。
- **IPC/preload**：`transfer:list/cancel/resume/remove/clearFinished/fail/startUpload`；`p2p.getPathForFile`（Electron 45 移除 File.path，用 webUtils）。
- **面板**（TransfersView.vue）：全部/进行中/已完成/已取消/已中断五标签（计数徽章）+ 表格（类型/对端/进度条/状态含错误 tooltip/时间）+ 取消/续传/删除/清除已结束；实时 `transfer:updated`。
- **测试**：transfer-store.test.ts（6 用例）、p2p-e2e 新增 12MB 直推 + 中断续传端到端（断点续传仅补发剩余）。
