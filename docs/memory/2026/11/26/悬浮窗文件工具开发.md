## 实际需求梳理

1. 构建双模式文件工具（命名 Lattice）：客户端模式连远程服务（未连接强制填 IP/端口/账号/密码），服务端模式自建（监听端口、账户管理、目录权限）。
2. 技术栈：electron-vite + Element Plus + SQLite（better-sqlite3）。
3. 悬浮窗：圆形悬浮球置顶可拖动，点击展开主界面。
4. 权限：目录白名单 + 可继承树形权限；账户密码可固定或随机生成；Windows 关闭隐藏到托盘；兼容 Windows 10+ 与 Ubuntu 24+。
5. 文件上传下载用局域网 P2P 直连传输。
6. 通过选项确认的细节：
   - P2P 方案：仅局域网直连（不做公网穿透、不做 Hyperswarm）
   - 连接协议：WebSocket + 自研 JSON 协议
   - 权限粒度：目录白名单 + 可继承的树形权限
   - 打包：Windows（NSIS）+ Ubuntu（AppImage/deb）双端
   - 窗口形态：圆形悬浮球 + 点击展开主窗口
   - 端口（WS 47100 / P2P TCP 47101 / UDP 发现 47102）可用，但设置页须提供可调整项
   - 传输接收确认：可设置，默认需要确认
7. 自发现功能：先提出（默认关闭、主动开启），随后明确取消，未实现。
8. 文档落库：最终计划写入 `docs/PLAN.md`。
9. Windows 打包：用户要求后准备 Docker 交叉打包（NSIS x64），拉取 electronuserland/builder:wine 镜像后命令超时，用户改为先调试运行，打包搁置。
10. 连接交互重构：由单连接改为多连接 + 多选项卡模式（每连接一个选项卡，内部切「文件/传输」子页）。

## 需求/问题描述

- 从零搭建完整可运行的双模式文件工具（项目目录初始为空）。
- 连接页与文件页/传输页分离在侧边栏、主进程仅单个 LatticeClient 实例，多任务时状态互相覆盖，用户反馈"容易让人搞混搞糊涂"。

## 解决方案

- 分层架构：`src/shared`（协议/权限/路径防护/P2P 帧）+ `src/main`（服务端/客户端/P2P/窗口/存储）+ `src/preload`（contextBridge 暴露 window.api）+ `src/renderer`（floater 悬浮球 + main 主界面）。
- 权限模型：7 个权限位（READ/WRITE/RENAME/DELETE/UPLOAD/DOWNLOAD/TRANSFER），子目录默认继承父级、可显式覆盖，沿祖先链求解最近覆盖生效；服务端对每个操作二次校验。
- 安全：scrypt 加盐口令、路径 `..`/绝对路径/NUL/符号链接逃逸校验、一次性 P2P token（5 分钟有效）、失败登录锁定、审计日志。
- P2P：UDP 定位已授权对端 + TCP 直连，帧协议（HELLO/MANIFEST/CHUNK/ACK/DONE/DECISION/ERROR），64KB 分块、SHA-256 校验、接收端按 transfer grant 动态解析写入根目录。
- 多连接改造：新增 `ConnectionManager`（每连接独立 LatticeClient），`client.request(id, method, params)` 按 id 路由；渲染层 `WorkspaceView` 卡片选项卡（状态点 + 可关闭）+ `SessionView`（文件/传输子页）。
- 依赖源：`.npmrc` 全量指向 npmmirror（registry/electron_mirror/electron_builder_binaries_mirror）。

## 踩坑结论

1. `openDatabase()` 对本地库复用 `user_version` 导致 LocalStore 迁移被跳过（报 no such table: app_settings）→ 本地库改用独立版本表 `local_meta`。
2. `PathViolationError` 未映射错误码 → 服务端统一归一化（PATH_VIOLATION/NOT_FOUND 等）。
3. 对目标路径做 `realpath` 在删除后自检失败 → 以白名单根目录为真实边界做前缀校验。
4. Vite 打包后 `node:fs` 具名导入失效（realpathSync is not a function）→ 改 `fs.realpathSync`。
5. 传输授权权限判断误用位与（`DOWNLOAD & TRANSFER` 恒为 0）→ 改 `hasPermission` 显式检查。
6. `electron-vite dev` 不接受 Electron CLI 参数（`--no-sandbox` 报 CACError）→ 用 `ELECTRON_DISABLE_SANDBOX=1` 环境变量；主进程内对 Linux 追加 `--no-sandbox --disable-gpu --disable-dev-shm-usage` 兜底。
7. npmjs 直连超时/TLS 错误 → `.npmrc` 固定 npmmirror；Electron 二进制需 `ELECTRON_MIRROR=... node node_modules/electron/install.js` 手动补装。
8. electron-builder 出 deb 需 package.json 提供 author.email 与 homepage，linux.maintainer 需显式设置。
9. Wayland 桌面下 xdotool/wmctrl 探测不到窗口 → 主进程 `attachDebug` 用 `executeJavaScript` 探测渲染挂载与正文文本验证界面。
