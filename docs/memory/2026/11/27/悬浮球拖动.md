# 悬浮球拖动

- 归档日期：2026/11/27
- 类型：缺陷处理（feedback）
- 来源：本会话（悬浮球拖动不可用修复）
- 梳理汇入时间：2026/11/27 10:17

## 用户提示词

> 悬浮按钮需要可以拖动

（口误说明："悬浮按钮"即悬浮球/Lattice 悬浮窗 FloaterApp，文档中固定称"悬浮球"。）

## 实际需求梳理

悬浮球设计上"可拖动、点击展开主界面"（见 PLAN.md 4.1、README），但实际无法拖动，要求修复拖动功能，且不得破坏点击展开行为。

## 问题原因

- `FloaterApp.vue` 中 `.floater` 设置 `-webkit-app-region: no-drag` 且铺满整个 72×72 窗口，等于全窗口无可拖区域，系统拖动不生效。
- 若简单改成 `drag`：系统 drag 区域会吞掉 click 事件，"点击展开主界面"会失效，不能直接改。

## 解决方案

手动拖动方案（拖动/点击智能区分）：

1. **主进程 `src/main/index.ts`**：新增 `window:floaterMoveBy` IPC，按增量 `setPosition` 移动窗口；用 `screen.getDisplayNearestPoint` 约束在最近显示器工作区内（至少留 12px 可见，防止拖丢）；悬浮球尺寸 72 提取为模块级常量 `FLOATER_SIZE`。
2. **preload `src/preload/index.ts`**：`window.api.window.moveFloaterBy(dx, dy)` 暴露给渲染层。
3. **渲染层 `FloaterApp.vue`**：
   - 用 `mousedown/mousemove/mouseup` + `screenX/screenY` 增量调用 IPC 移动窗口；
   - 累计移动距离 > 4px（`DRAG_THRESHOLD`）判定为拖动；`mouseup` 时未超阈值按点击处理 → `openMain()`，两个行为互不干扰；
   - 现有主进程 `moved` 事件监听自动持久化新位置（local.db），重启后位置保留；
   - 光标改为 `cursor: grab`；body 上的 `-webkit-app-region: drag` 移除（与手动拖动冲突，无用）。

## 涉及文件

- `src/main/index.ts`（新增 floaterMoveBy IPC、FLOATER_SIZE 常量）
- `src/preload/index.ts`（window.moveFloaterBy）
- `src/renderer/src/floater/FloaterApp.vue`（拖动逻辑 + 样式）

## 验证结论

`npm run typecheck` 通过（typecheck:node + typecheck:web 均 0 错误）。未做实机拖动验证，待 `npm run dev` 确认：按住悬浮球可任意移动，轻点仍展开主界面。

## 踩坑结论

- Electron 无边框透明窗口中，`-webkit-app-region: drag` 区域内的鼠标事件被系统消费，DOM click 不触发——既要拖动又要点击的控件必须走"手动 mousemove + IPC 移动窗口 + 位移阈值区分点击"的组合，不能依赖 app-region。
