# 传输面板独立化

> 归档日期：2026-11-27 ｜ 类型：需求开发（need），含缺陷处理（feedback） ｜ 来源：AI 编码会话（OpenCode + GLM） ｜ 梳理汇入时间：2026-11-27

## 用户提示词（原话，一字不改）

> 1、待确认的传输 应该独立一个菜单和连接tab无关系，因为你不连接别人，别人也会推送给你文件
> 2、接收、推送都需要看看 现在传了多少量

## 实际需求梳理

1. **传输面板脱离连接 tab**：待确认请求来自本机服务端（对方可不经本机主动连接直接推送），传输记录也是全局的，不应挂在某个连接选项卡下。
2. **进行中传输显示字节量**：接收（p2p-recv）/推送（p2p-send）在传输中要能直观看到已传了多少，而不是只有百分比。

## 方案与实现

- **侧栏新增独立「传输」菜单**（`src/renderer/src/main/App.vue`）：整页承载原 `TransfersView`（待确认请求 + 传输记录）；`SessionView.vue` 移除「传输」子页（只剩文件）。
- **事实依据**：`client:pendingTransfers`/`decideTransfer` 是全局 IPC，不依赖任何连接；`TransfersView` 原有的 `connectionId` prop 从未使用（`void props`），天然全局。
- **侧栏角标**：有新待确认请求时菜单显示数量。因 `TransferManager.decide`/60s 超时均不广播事件，采用「`transfer:incoming` 事件即时刷新 + 3 秒轮询内存接口 `listPending()` 兜底」。
- **已传量显示**（`TransfersView.vue`）：进行中记录进度条下恒显传输量文案 `volumeText()`——有总量显示 `已传 X / Y`，无总量显示 `已传 X`；速度与剩余时间跟在其后。
- **页面标识**：按《页面弹窗标识规范》在 `usePageRegistry.ts` 登记固定页面 ID `transfers: 'a004'`（FIXED_PAGE_IDS + PAGE_DIALOG_BASE），避免每次启动随机换号无法回溯反馈。

## 踩坑（feedback）

- 简化 `SessionView` 模板时漏删一个 `</div>`，vite 报 `Invalid end tag` 编译失败——**改模板闭合结构时必须整体核对配对**，typecheck 前先看 dev 编译输出。
