# 批量上传与多选下载

> 归档日期：2026-11-27 ｜ 类型：需求开发（need） ｜ 来源：AI 编码会话（OpenCode + GLM） ｜ 梳理汇入时间：2026-11-27

## 用户提示词（原话，一字不改）

> 上传可以选择多个目录或多个文件

> 下载同理

## 实际需求梳理

1. **上传多选**：文件页「上传」支持一次选择**多个文件**或**多个文件夹**（Windows 原生对话框无法文件/目录混选，需分两个入口），目录上传保留内部结构。
2. **下载同理**：文件列表支持勾选多项（文件+目录可混合）批量下载，一次会话完成，对方（服务端）只确认一次。

## 方案与实现

### 批量上传（主进程展开 + 顺序队列）

- **选择**（`src/main/index.ts`）：新增 `dialog:pickUpload` IPC，`mode: 'file' | 'dir'` 分别用 `showOpenDialog` 的 `openFile`/`openDirectory` + `multiSelections`，返回绝对路径列表。
- **展开**（`src/main/transfer-runner.ts`）：`expandSources()` 递归展开目录（lstat 不跟随符号链接），远端相对路径用 `/` 拼接并保留顶层名；**空目录**不会随 uploadInit 隐式创建，单独收集后先发 `mkdir` 补建（无 WRITE 权限时忽略失败）。
- **执行**：`startUploadBatch()` 每个文件一条 upload 传输记录（可单独取消/断点续传），经 `enqueue()`/`pump()` **顺序队列**逐个上传，避免大量并发传输；排队中被取消的记录直接跳过。
- **UI**（`FilesView.vue`）：工具栏「上传」改 el-dropdown split-button（点击默认上传文件，下拉可选文件夹），右键空白菜单拆「上传文件 / 上传文件夹」；渲染层不再用 `<input type="file">`（删除 webUtils.getPathForFile 旧路径）。
- preload 暴露 `dialog.pickUpload`、`transfers.startUploadBatch`。

### 批量下载（勾选 + 单会话多路径推流）

- **UI**（`FilesView.vue`）：列表视图 el-table 加 `type="selection"` 勾选列；卡片视图每张卡加右上角复选框；工具栏新增「下载选中(N)」（需 TRANSFER 权限），目录内容刷新时清空勾选。
- **协议**（`src/main/server/service.ts`）：`p2pPush` 命令新增 `paths?: string[]`——`preparePush` 改用 `collectTargets()` 收集多路径文件（目录递归展开、按 relPath 去重、要求非空），单条 manifest 一次推流，**对方只确认一次**；发送记录名「N 个项目」、remotePath「首项 等 N 项」；resume JSON 存 `paths` 供续传。
- **接收端**：多选时 `prepareReceive` 以 `isDir: true` 选一个目标文件夹，P2P 接收端本就按 manifest relPath 落盘（`p2p/transfer.ts` 已支持多文件），无需改动。
- `resumePush` 同步支持多路径断点续传；单文件下载流程（保存对话框 + rename）完全不变。
