# 接收传输记录

> 归档日期：2026-11-27 ｜ 类型：缺陷处理（feedback） ｜ 来源：AI 编码会话（OpenCode + GLM） ｜ 梳理汇入时间：2026-11-27

## 用户提示词（原话，一字不改）

> 别人推送的我在传输中看不到

> 二次传输竟然不需要确认了

> 是传输第二个文件

> 能看到接收确认了，但是还是看不到接收传输的列表信息

## 实际需求梳理

1. 对端把文件推送过来后，「传输」面板的传输记录列表里看不到这条接收传输（待确认卡片能看到，接受后记录消失）。
2. 用户补充观察：对端传第二个文件时没有弹接收确认。澄清后确认弹窗其实能看到（此前只在「传输」页内展示，靠侧栏角标发现）；真正的问题是接收记录始终不出现。

## 问题定位（根因）

- **接收方向从来不创建传输记录**。记录只在两处「本机主动发起」时创建：
  - `p2p:prepareReceive`（index.ts，本机发起下载，选完保存位置建 `p2p-recv`）
  - `TransferRunner.startUpload`（本机上传到远端，建 `upload`）
- 对端推送的两条路径在接收端只有「确认」没有「记录」：
  - **WS 上传**（对端文件页点「上传」→ 我方服务端 `uploadInit`）：`ensureUploadAccepted` 确认后直接 `createUpload` 落盘，`uploadChunk/uploadFinish/uploadAbort` 全程不落库。
  - **P2P 对端推送**（对端 `p2pPush` 推流到我方 P2P 端口）：`requestConfirm`/`onProgress`/`onDone`/`onInterrupted` 只按 `getBySession(sessionId).find(kind==='p2p-recv')` **更新**已存在记录，查不到就什么都不做。
- **关键陷阱**：4cc79bb 之后 `transferGrant` 接收方向全部 `preAuthorized=true`（确认在授权时已完成），`requestConfirm` 走预授权分支直接放行——补建记录的代码必须放进**预授权分支**，放在确认弹窗之后永远走不到。
- 二次确认问题结论（无代码改动）：`ensureUploadAccepted` 缓存 key 为 `accountId:root:path`，5 分钟滑动续期，**同路径**重传/重初始化免二次确认（4cc79bb 设计如此，避免中断重连重复弹窗）；不同路径按代码会重新弹确认。

## 解决方案（提交 d5e4073，已推送）

1. **新传输类型 `ws-recv`**（protocol.ts）：`TransferKind` 增加 `'ws-recv'`，面板标签「接收」（绿色）。`resumable()` 不含它（WS 接收端无法自行续传，发送端重新上传即可）。
2. **WS 上传接收落记录**（service.ts `dispatch`）：
   - `uploadInit` 接受后 `store.create({ kind:'ws-recv', peer:s.username, name, remotePath, localPath:ops.resolvePath(root,path), total:size })`，并登记 `uploadRecs`（uploadId → 记录 id）；
   - `uploadChunk` 按 base64 长度换算落盘字节数（含 `=`/`==` padding 修正）调 `updateProgress`；
   - `uploadFinish` → completed；`uploadAbort` → cancelled（对方取消了传输）；`socket.once('close')` → interrupted（连接中断）。
   - 应用启动时 `interruptAll()` 兜底把遗留 active 标记为 interrupted（已有机制）。
3. **P2P 对端推送补建记录**（service.ts）：
   - 新增 `createRecvRecord(g, from, info)`：`requestConfirm` 预授权分支 `rec` 不存在时调用（对端推送场景）；确认弹窗路径（非预授权授权）接受后同样补建；
   - 记录带 `resume: JSON.stringify({ dir: g.root })`——`validateToken` 的续传兜底分支读 `ctx.dir` 自动重建授权，对端单方面续传可以走通；
   - 本机发起的下载 `rec` 已预建，走原有 update 分支不受影响。
4. **FileOps.resolvePath**（fs-ops.ts）：公开解析保存绝对路径的方法，供记录 `localPath` 展示。
