# 传输暂停与打开目录

> 归档日期：2026-11-27 ｜ 类型：需求开发（need） ｜ 来源：AI 编码会话（OpenCode + GLM） ｜ 梳理汇入时间：2026-11-27

## 用户提示词（原话，一字不改）

> 传输新增暂停
>
> 传输列表行新增打开目录

## 实际需求梳理

1. **传输新增暂停**：传输面板进行中的记录可「暂停」（保留断点、状态标已暂停），之后可「继续」原地恢复，不必走完整断点续传重放；暂停期间取消仍可用。
2. **传输列表行新增打开目录**：每条传输记录的操作列加「打开目录」，快速定位本地文件（上传源 / 接收目标）。

## 方案与实现

### 暂停（按类型分策略）

| 类型 | 暂停方式 | 继续方式 |
| --- | --- | --- |
| upload | 挂起 TransferRunner 分块循环（服务端上传会话保留，恢复免重初始化） | 唤醒循环原地继续 |
| p2p-send | 挂起 LatticeServer 推送任务（socket 保留） | 唤醒推送任务 |
| p2p-recv | 新 WS 命令 `p2pPushPause` 通知发送端挂起推流 | `p2pPushResume` 唤醒；对端任务已不在（如对端重启）自动回退完整续传 |
| ws-recv | 暂不支持（发送节奏由对端控制），UI 不显示暂停按钮 | — |

- **协议状态**：`TransferState` 新增 `'paused'`（shared/protocol.ts）。
- **发送侧挂起**：`sendFiles` 新增 `shouldPause` 选项，分块循环每块前轮询（150ms 间隔），暂停期间 `shouldAbort` 仍生效（取消可打断暂停）。
- **服务端**：pushJobs 任务加 `paused` 标记；新增 `pausePush`/`resumePausedPush` 方法与 WS 命令 `p2pPushPause`/`p2pPushResume`；续传免确认（requestConfirm）、cancelPush、p2pPushStop 的状态匹配都补上 paused。
- **双任务防护**：executePush 注册任务前先 abort 同会话旧任务，防「暂停后走完整续传」出现双任务双 socket。
- **runner**：新增 `pause()`；上传任务挂起前先把最新断点（offset/uploadId）持久化到 resume 上下文（防暂停后杀进程丢进度）；`cancel()` 放行 paused 记录（唤醒挂起再中止）；`resume()` 优先原地唤醒（upload 看 jobs 存活 / p2p-send 看 resumePausedPush / p2p-recv 发 p2pPushResume），失败回退既有续传流程。
- **UI**（TransfersView.vue）：进行中行加「暂停」，已暂停行「继续」，新增「已暂停」页签（橙色 badge），暂停记录保留进度条（warning 色、无速度）；`pausable()` 限定 upload/p2p-send/p2p-recv 三类。

### 打开目录

- 新 IPC `transfer:reveal`（index.ts）+ preload `api.transfers.reveal`：
  - 目标存在且是文件 → `shell.showItemInFolder`（打开所在目录并选中）；
  - 是目录（批量接收目录）→ `shell.openPath`；
  - 文件尚未落盘（刚取消/暂停）→ 退回打开所在目录；目录不存在报「目录不存在或已被删除」。
- p2p-send 记录 localPath 为空：从续传上下文还原源文件位置（`join(root, paths[0] ?? path)`）。

## 注意事项

- 已暂停记录不被「清除已结束」清掉（clearFinished 只清 completed/cancelled）；应用退出保持 paused，重启后「继续」走回退续传路径。
- 遗留小竞态：p2p-recv 暂停请求到达发送端时其推送任务可能尚未注册（确认→开始窗口极窄），此时挂起不生效，属低概率可接受。
