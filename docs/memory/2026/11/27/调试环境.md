## 问题与修复（feedback）

1. **Electron 二进制缺失**：首次 `npm run dev` 报 `Error: Electron uninstall`，`node_modules/electron/dist` 和 `path.txt` 均缺失（此前依赖安装未下载成功）。修复：
   ```powershell
   $env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'; node node_modules\electron\install.js
   ```
   （镜像已配在 .npmrc，但 npm 11+ 对 .npmrc 自定义键只告警不生效，故用环境变量。）
2. **electron-vite dev 不监听主进程**（详见 传输确认与进度.md）：主进程改动不重编译，dev 脚本加 `--watch` 修复。
3. **Windows 测试 EPERM**：41 项测试中 9 个失败，全是 `rmSync` 删临时目录报 `EPERM`——better-sqlite3 连接未关闭，Windows 不允许删除已打开文件（Linux 允许，故 Ubuntu 上不暴露）。修复：4 个测试文件（e2e/multi-client/p2p-e2e/transfer-store）清理前先 `db.close()`。教训：**Windows 上 SQLite 库连接必须先关再删目录**。
4. **npm 副作用**：Windows 上跑 npm 会改写 package-lock.json（删掉其他平台 optional 依赖、加 hasInstallScript），已还原不提交，避免影响 Ubuntu 侧安装。

## git 推送代理

- 7890 代理端口已失效；探测本机监听端口发现 **7897（Clash Verge 默认混合端口）可用**。
- 推送命令：`git -c http.https://github.com.proxy=http://127.0.0.1:7897 push origin main`。
- 直连 GitHub 时通时不通（Connection reset / 443 超时），稳定推送走 7897。建议把全局配置更新为 7897（尚未改）。
- **绕过代理法（11/27 第四轮实测）**：代理未启动时，`git -c http.https://github.com.proxy= push` 置空该 URL 级代理直连推送成功（74f02ba、d5e4073 两次均通）。该代理配置藏在 `.gitconfig` 的 `[http "https://github.com"]` 小节，`git -c http.proxy=` 无效，必须按 URL 键名覆盖；`git config --show-origin --list | grep proxy` 可定位。

### 事实与结论

- 推送 `8dd908a` 时 **7890 代理未运行**（`Test-NetConnection 127.0.0.1 -Port 7890` 为 False），首次推送报 `Failed to connect to 127.0.0.1 port 7890`。

- **实测补充**：`git -c http.https://github.com.proxy= push origin main` 直连推送成功（d5e4073..8dd908a）。至此直连已三次实测可通（74f02ba、d5e4073、8dd908a），「直连不稳定」结论仅对当时网络成立，代理未启动时直连是可行的首选。
